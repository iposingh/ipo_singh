IPO SINGH — PERMANENT ENGINEERING RULES

1. Preserve existing working functionality.
2. Read relevant files before making changes.
3. Implement only the scope of the current prompt.
4. Use TypeScript with strict type checking.
5. Use modular, feature-based architecture.
6. Avoid giant components, services and route files.
7. Use reusable components and shared contracts.
8. Never hardcode API keys, credentials or secrets.
9. Never expose IPO Guru credentials to web/mobile clients.
10. Never call IPO Guru directly from public clients.
11. Use the IPO Guru API v2 documentation, not v1.
12. Never fabricate IPO, GMP or subscription data.
13. Clearly distinguish missing, zero and stale values.
14. All financial values must have explicit units.
15. Show timestamps in Asia/Kolkata where relevant.
16. Cache upstream responses and deduplicate requests.
17. Respect API rate limits and commercial data rights.
18. Use server rendering for indexable public IPO pages.
19. Design mobile-first, accessible and responsive UI.
20. Use the approved Growth Arrow Green design theme.
21. Keep business logic independent of API providers.
22. Validate all external data at runtime.
23. Write meaningful tests for calculations and services.
24. Do not run destructive commands without approval.
25. Never modify production data during development.
26. Never silently hide integration errors.
27. At the end of each task, report changed files,
    tests run, issues found and next prerequisites.
28. Do not begin the next prompt automatically.
